# 参考情報解析

## 情報源の扱い
- 公式データを事実の基準にする。
- ボートレース日和、記者予想、YouTube予想家などは補助仮説として扱う。
- 他者の買い目そのものをコピーせず、展開判断や条件分岐だけを抽出する。

## 抽出対象
平均ST、スタート順位、コース別攻め筋、壁艇、まくり/差し/まくり差し条件、当地水面特性、展示後の変化、選手タイプ別の再現パターン。

## 採用条件
1. 現行AIの固定思想と矛盾しない
2. 公式データで再現条件を定義できる
3. 既存予想との比較ができる
4. 複数レースで良化を確認できる

未検証の参考理論をそのまま本番ロジックへ入れない。

## 外部理論をshadowで検証する手順

YouTube動画の要約などから理論を受け取ったら、次の順で検証する（例：`docs/wake-crossing-head-gate-v1.md`、2026-10-21）。

1. **判定ルールに落とす**：理論を「どの艇・どの条件で・どう扱うか」の判定に言い換え、閾値（走数下限、必要回数など）と対象外の条件を決める。既存の重みや評価と重なる部分は、既存実装のどこにあるかを先に確認する。
2. **結果を見る前に固定する**：判定条件・比較する案（A=現行、B/C=変更案）・集計方法・証拠が十分とみなす件数を、コードの固定値とdocsに書いてから実データを流す。憲章に合わせ、数字だけで新しい券を足す案は避けるか、根拠を構造化して残す。
3. **締切前保存データだけを使う**：入力は `data/predictions` の締切前保存予想と `data/results` の公式結果。`scripts/analysis-input-contract.js` の締切前判定を通し、結果後のデータで過去の判定を後付けしない。予想時に必要な情報が保存されていない期間は、公式結果原本からレース前日までの窓だけで再構築し、保存済みと重なる期間で一致率を確認する。
4. **期間を分ける**：結果を見ながら案を作った期間（explored）と、案を固定した後に初めて見る期間（holdout）を分けて集計する。exploredでだけ良い案は採用候補にしない。
5. **shadowとして実装する**：本番予想・買い目・UI・noteは変えず、`productionChanged: false`・`usableForPrediction: false`・`automaticApplication: false` を出力に含める。保存データは読み取りのみ。fixtureテストで判定・境界・締切後除外・projection parityを確認する。
6. **PRで受け渡す**：Draft PR、Codexレビュー、既存CIを通し、`docs/development-approval.md` の手順でマージする。
7. **本番採用は別承認**：検証で良化しても自動で採用しない。結果を示し、予想ロジック変更として本人の承認を別に得る。
