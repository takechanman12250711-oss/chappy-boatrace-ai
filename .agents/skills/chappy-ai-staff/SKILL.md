# チャッピーAI社員の分業

2026-11-13本人依頼の双方の無人起動では `docs/ai-staff-claude-cloud-task.md` を使う。既存の毎時勤務を受信側に保ち、本人がClaudeアカウント内で保存する専用ラベル限定Cloud scheduled taskへ同じPRを渡す。`scripts/ai-staff-handoff.cjs` のrequest・claim・receiptでheadと最大3往復を照合し、実際のClaude実行・返却と次回チャッピー勤務の受領を確認する。社員定義やラベル追加だけを稼働証拠にしない。既存の提案下書き・限定Work受信・他の停止タスクは変更しない。

最初に最新mainの `AGENTS.md` と `docs/ai-staff-operations.md` を読む。社員の名前と担当は `staff.html` を維持し、既存のスキル・保存結果・Issue/PRを再利用する。

1. 主担当はカイの統括役として、依頼の範囲・完了条件・作業ID・次の担当を整理する。単独で済む作業に全社員を起動しない。
2. 独立した仕事だけを必要な社員へ委任する。まず2〜4名程度とし、担当の正本 `.claude/agents/chappy-<社員の英名>.md` の本文、対象・入力SHA/時刻、編集範囲、返却条件を渡す。この会話では実際に使えるサブエージェントを使い、Claudeの設定ファイルがCodexへ自動登録されたとは扱わない。
3. 同じファイルの編集担当は1名。入力や先行成果を必要とする作業は順に渡す。実装と独立レビューを分ける。
4. 担当は、確認事実・成果物・検査と対象head・未確認/停止理由・次の1件を主担当へ返す。必要な記録は既存の同じIssue/PRへ集約し、不要な台帳や重複Issueを増やさない。
5. 主担当は結果を統合し、何が完了し、何が残り、次に何を進めるかを短く返す。割り当てただけの仕事、未取得の数字、起動していない社員を実行済みへ読み替えない。
6. Claude Code側の社員と協業するときは、運用文書の「Claude Code側の社員と協業する」に従い、送信元・受信先の実行元と担当、受領状態、編集担当、固定headを同じPRへ残す。相手の既存チームを保持し、依頼の準備を受領・起動と扱わない。実装と独立レビューは両方向で引き継げるが、同じファイルの編集は重ねない。

社員定義は実行中の会話や、本人が有効にした無人タスクの中で使う。無人運用は `docs/ai-staff-autonomous.md` を読み、依頼済みの対象・頻度・利用枠・実行者・接続を確認する。定義の存在だけで閉じた後の起動を保証せず、既存Actionsの実行を社員モデルの判断と説明しない。Claudeへの本人認証・Codexとの直接接続とは別に扱う。

Claude Codeでは、定義を含むcheckoutのプロジェクト読込で `.claude/agents/chappy-*.md` が検出・委任の対象になる。main反映だけで全既存セッションが読込済みとはせず、対象headと定義の検出を確認する。検出は本人の明示指定の有無とは別であり、既存チームの再作成や設定上書きの許可ではない。実際の委任は依頼範囲・担当確認に従う。相手のボードIDの申告をCLIの呼出名へ読み替えない。

停止済み監視の一括再開、新cron、有料API、追加契約、自動マージは行わない。このサービスが登録する無人のPR開発勤務は本人が確認した1件だけを使い、実行回数や対象を勝手に広げない。Claude側の既存の提案下書き運用とは責任範囲を分け、相手のタスクを変更・新設しない。相手からの申告と実設定・予定実行の検証を分ける。予想/結果/原本/買い目をこの設定で変更せず、予想採用や公開は対応する既存スキルと本人方針に従う。main反映は既存の最終確認を維持する。
