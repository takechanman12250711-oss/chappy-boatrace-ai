# チャッピーボートレースAI憲章

制定日: 2026年7月21日
管理者: あっくん

## 1. 目的

この憲章は、レース選定・予想・買い目・note原稿・結果検証を自動化しても、合意済みの判断基準を変えないための最上位ルールです。

## 2. 予想の優先順位

判断は必ず次の順序で行います。

1. 展開
2. コース
3. ST・スリット
4. 展示・足
5. 残し・拾い
6. 当地・水面
7. 技量
8. モーター

後順位の数字だけで、前順位から成立した展開を覆しません。

## 3. 固定原則

- 基本は内側優位とする。
- 2コース差し、4号艇の残しなど、現実的な残し・拾いを軽視しない。
- 数字やオッズだけで買い目を作らない、追加しない、削除しない。
- オッズは買い目作成後の表示・分類・資金配分にだけ使う。
- 本線が成立しないレースは見送る。
- 艇番に関係なく、評価済みの攻め・追走・残し・拾いは、成立する着順候補を点数制限より先に生成する。
- 候補を外す場合は、評価を下げず、比較対象と除外理由を構造化して残す。
- 実戦厳選は基本5点、通常5〜7点とする。
- 流しは、同じ正式展開と同じ1着・2着軸を共有し、2着残しと3着拾い・残りの役割評価がともに65点以上となる正確な2券がそろった場合だけ、2券を一組として採用する。1券だけを流しと呼ばず、根拠のない全流しや点数合わせは行わない。
- 流し2券と通常の万舟・穴1券は同時に採用しない。流しが成立した通常枠は本線3点・押さえ2点・流し2点の最大7点とし、流しが成立しない場合だけ通常の万舟・穴候補を比較する。
- 独立した成立展開が複数ある場合だけ最大10点まで許容し、弱い買い目で10点まで埋めない。
- 候補の成立要件は購入義務ではない。基本5点を独立展開で押し出さず、構造化根拠と役割評価65点以上を満たす候補だけを比較する。
- 本線・押さえ・流し・穴の表示根拠はカテゴリごとに解決し、別カテゴリのコメントを流用しない。
- 新エンジン・新モーター・新燃料の時期は、モーター数字を過信せず、展示・ST・今節気配・技量・当地・水面を優先する。

## 4. 自動化の権限

自動化してよい処理:

- 公式データの取得と保存
- 締切前レースの比較、選定、見送り判定
- 合意済みロジックによる予想と、基本5〜7点・成立展開が複数ある場合のみ最大10点の生成
- note原稿の下書き生成
- 公式結果との照合、統計更新、改善候補の作成

自動化してはいけない処理:

- 予想の優先順位を変える
- 固定原則を弱める、削除する
- 数字やオッズだけで買い目を変える
- 管理者の同意なしに予想ロジックや重みを変更する

## 5. 変更手続き

予想ロジックを変更するときは、実装前に次の3点を説明します。

1. 何を変えるか
2. なぜ変えるか
3. 予想・買い目・表示へどう影響するか

管理者の明確な同意後にだけ変更します。結果分析は改善案の提示まで自動化できますが、自動でロジックへ反映しません。

## 6. 機械検査

機械判定用の正本は `config/chappy-charter.json` です。`scripts/check-charter.js` と GitHub Actions が、憲章の必須項目と実装上の安全条件を検査します。

## 7. 展示・足理論 Ver2

- 展示・足は総合点の9％枠だけで評価する。
- 展示タイム6艇取得時は「公式展示モード」、展示・一周タイム6艇取得時は「展示・一周フルモード」とする。
- 0.01秒以内は同等評価とする。
- 欠損・重複・異常値がある場合は、新しい展示点を加えず中立50点とする。
- 一周タイムを展示タイムから推測しない。
- 展示STはST・スリットだけで評価する。
- ダブルタイムと新サムは展示・足100点内へ統合し、展開・役割・着順候補へ別枠加点しない。
- モーター理論では展示・一周・STを再加点せず、整備効果の確認条件としてだけ使用する。
- 判定モードと取得元を表示する。

## 8. 自動選定V2のシャドー検証

- 現行の予想・買い目・70点基準・note採用から分離して保存する。
- 締切2分前以前に観測したスナップショットだけを校正候補とする。
- 6艇の出走・公式進入・平均ST・展示ST・展示タイム・技量・モーターと、風向・風速・波高を完全データの必須条件とする。
- 潮汐場では現在潮位または潮流も必須とする。
- 展開、コース、ST・スリット、展示・足、残し・拾い、当地・水面、技量、モーターを独立した0〜100点で保存する。
- 暫定値も診断用に保存できるが、8項目がすべて正式値になるまで校正対象にはしない。
- オッズと公式結果は採点に使わない。
- ロジック、設定、参照データの識別情報を保存し、異なる世代を同じ母集団として扱わない。
- 既存データをV2相当として遡及補完しない。
