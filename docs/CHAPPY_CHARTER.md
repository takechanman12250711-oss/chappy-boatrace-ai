# チャッピーボートレースAI憲章

制定日: 2026年7月21日
管理者: あっくん

## 1. 目的

この憲章は、レース選定・予想・買い目・note原稿・結果検証を自動化しても、合意済みの判断基準を変えないための最上位ルールです。

## 2. 予想の優先順位

判断は必ず次の順序で行います。

1. 展開
2. コース
3. ST・スリット
4. 展示・足
5. 残し・拾い
6. 当地・水面
7. 技量
8. モーター

後順位の数字だけで、前順位から成立した展開を覆しません。

## 3. 固定原則

- 基本は内側優位とする。
- 2コース差し、4号艇の残しなど、現実的な残し・拾いを軽視しない。
- 数字やオッズだけで買い目を作らない、追加しない、削除しない。
- オッズは買い目作成後の表示・分類・資金配分にだけ使う。
- 本線が成立しないレースは見送る。
- 実戦厳選は基本5点、最大7点とする。
- 新エンジン・新モーター・新燃料の時期は、モーター数字を過信せず、展示・ST・今節気配・技量・当地・水面を優先する。

## 4. 自動化の権限

自動化してよい処理:

- 公式データの取得と保存
- 締切前レースの比較、選定、見送り判定
- 合意済みロジックによる予想と最大7点の生成
- note原稿の下書き生成
- 公式結果との照合、統計更新、改善候補の作成

自動化してはいけない処理:

- 予想の優先順位を変える
- 固定原則を弱める、削除する
- 数字やオッズだけで買い目を変える
- 管理者の同意なしに予想ロジックや重みを変更する

## 5. 変更手続き

予想ロジックを変更するときは、実装前に次の3点を説明します。

1. 何を変えるか
2. なぜ変えるか
3. 予想・買い目・表示へどう影響するか

管理者の明確な同意後にだけ変更します。結果分析は改善案の提示まで自動化できますが、自動でロジックへ反映しません。

## 6. 機械検査

機械判定用の正本は `config/chappy-charter.json` です。`scripts/check-charter.js` と GitHub Actions が、憲章の必須項目と実装上の安全条件を検査します。

## 7. 展示・足理論 Ver2

- 展示・足は総合点の9％枠だけで評価する。
- 展示タイム6艇取得時は「公式展示モード」、展示・一周タイム6艇取得時は「展示・一周フルモード」とする。
- 0.01秒以内は同等評価とする。
- 欠損・重複・異常値がある場合は、新しい展示点を加えず中立50点とする。
- 一周タイムを展示タイムから推測しない。
- 展示STはST・スリットだけで評価する。
- ダブルタイムと新サムは展示・足100点内へ統合し、展開・役割・着順候補へ別枠加点しない。
- モーター理論では展示・一周・STを再加点せず、整備効果の確認条件としてだけ使用する。
- 判定モードと取得元を表示する。
