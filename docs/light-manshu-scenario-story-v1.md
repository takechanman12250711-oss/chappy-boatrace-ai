# 「取れたらいいな」万舟シナリオ v1

> この文書は、既存穴候補1点へ説明だけを付けるv1の契約を記録する。2026-09-03に承認された別枠の複数参考舟券は、`light-manshu-ticket-board-v2.md` で独立して定義する。v1の既存互換は維持する。

更新日: 2026-09-03 JST

## 目的

通常予想がすでに保持している先頭の穴候補1点について、予想屋が軽く考えるような「もしかしたら」の筋を説明する。

考える順序は次のとおり。

1. スタートや1マークで何が起きるか
2. 誰が攻めるか
3. 誰が攻めについて行くか、または内で残るか
4. 誰が空いたところを拾うか
5. 道中力や選手の実力で着順が入れ替わる余地があるか
6. 既存の穴候補1点へ着地するか

これは高確率を断定する本線ではなく、筋が通っていて「取れたらいいな」と持っておく既存1点の説明である。

## 実装範囲

- 説明対象は `formations.longshot[0]`。最終統合後は、実際に残った `ticketSheets.hole[0]` へ再整合する。
- 3艇が重複しない正確な3連単だけを扱う。
- 正式主展開が成立したレースだけで説明する。
- 逃げ、2差し、3コース攻め、4カド攻めから、既存穴候補の頭と最もつながる展開を1つ選ぶ。
- 穴頭は、攻め艇そのもの、展開内の1着候補、内残し根拠、または外の連動・拾い根拠のいずれかで裏付ける。
- 逃げ成功の展開は逃げ艇が頭の券だけに使い、逃げ艇が着外になる券を「逃げ筋」として説明しない。
- 2着艇と3着艇が、選んだ展開の各着候補に入らない場合は、買い目を消さず説明だけを見送る。
- 実進入が変わった場合は枠番ではなく、公式展示進入の物理艇とコースの対応を使う。
- 説明上の役割は、攻め艇、内残し、追走、展開拾い、道中の押し上げに分ける。
- 「攻め場減少」など不利な根拠は、肯定的な拾いへ言い換えず、展開が開いた場合だけ残る条件付きリスクとして表示する。
- 道中の説明は、既存の道中候補に入り、道中役割点が65点以上の艇だけに使う。
- 選手実力の文言は、選んだ展開が正式主展開と一致し、その艇の技量理論が正式採用されている場合だけ使う。

## 表示例

### 4-5-1

4カドがスタートを決めて攻め切れれば4が先頭。5が攻めについて行き、1が内で残る。既存の `4-5-1` を「取れたらいいな」の攻め筋として説明する。

### 5-1-6

4が攻めれば5がその攻めに乗って先頭。1は内で残り、6は空いたところを拾う。6に既存の道中根拠があれば、一度位置が入れ替わっても道中で3着を取り返す可能性まで説明する。

## 変更しない境界

| 項目 | v1の扱い |
|---|---|
| 本番の展開シナリオ | 変更しない |
| 1着候補・印 | 変更しない |
| 本線・押さえ・フォーメーション・穴候補 | 追加・削除・置換・並べ替えをしない |
| 通常予想の点数 | 最大7点のまま |
| 実戦厳選 | 選定条件・順位・金額を変更しない |
| オッズ | 説明生成に使わない |
| 公式結果・払戻 | 説明生成に使わない |
| note・購入保存 | 変更しない |
| UI | 既存の万舟欄と既存フォールバック表示を使い、新しい画面を追加しない |

説明オブジェクトは `formations`、`possibilityCandidates`、`evidence.branches` の外に置く。これにより進行中の `outer-attack-ticket-shadow-v1` のA/B入力、候補プール、指紋を変えない。

## 3・4号艇頭昇格研究との区別

`docs/research/supported-lane34-head-promotion-closure-20260903.md` の `REJECT_AND_CLOSE` は維持する。

この機能は次を行わない。

- 3・4号艇を新しく1着候補へ昇格しない。
- 上位24候補、支持85・90点、反復7回、ST差0.03、展示タイム差0.03などの棄却済み条件を再利用しない。
- 2・3着を広げて買い目を増やさない。
- 既存穴候補とは別の夢舟券を追加しない。

既存の穴候補がすでにある場合に、その1点がどのようなスタート、攻め、残し、拾い、道中変化で成立するかを説明するだけである。

## 機械検証

- 代表筋 `4-5-1` と `5-1-6`
- 逃げ・差し・3攻め・4攻めの文言
- blocked艇を追走艇と誤表示しないこと
- 道中役割点64では不採用、65以上だけ説明すること
- 実進入入れ替わり時も物理艇を正しく扱うこと
- 2着・3着の元の役割を消さず、道中イベントを追加すること
- 選んだ展開の2着・3着候補と券順が一致しない時は説明を出さないこと
- 攻め場減少を肯定的な追走・拾いとして表示しないこと
- オッズ・結果を加えても説明と対象券が変わらないこと
- 通常予想、候補プール、外攻めA/B指紋が変更前と一致すること
- 通常経路とiPhone復旧経路の両方で、更新済みAIコアの専用キャッシュ世代を読むこと

出力には `usesOdds: false`、`changesTicket: false`、`selectionScope: existing-hole-candidate` を記録する。
