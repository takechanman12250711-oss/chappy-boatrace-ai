# 締切前入力の逃げ・外攻め比較

`scripts/compare-escape-frozen.cjs` は `escapeEvaluationEvidence` のある日次保存・不変noteを読み、現行と役割修正前、4コース攻めのイン比較候補を隔離VMで計算する。本番のJSは変更しない。

- 現行の本命頭・実戦券集合・全展開スコアが保存値と一致した行だけを比較する。欠損は現在のAPIや履歴で補わない。
- 6艇の公式進入・展示ST・展示タイムが揃った保存入力に限る。時刻・実行SHAだけの差で同じ集計を再保存しない。
- 日次primaryをverificationより優先し、noteは既存assess契約を通す。各レースは最新の適格な保存時点1件にまとめる。
- 公式結果のpending行が独立した公式結果ledgerの確定結果を隠さない。返還・不成立は除外し、払戻不明は0円にしない。
- 保存結果がない終了レースは既存公式result APIで最大24件・並列3件だけ取得する。取得対象は締切15分後以降。取得結果は比較レポート内に証拠として保存し、公式原本や元予想を更新しない。
- 金額は実戦券1点100円の仮定。通常候補・参考万舟を混ぜない。24場の0件・未確定・再現不一致も残す。

## 比較候補

`four-inner-start-guard-v1` は、既存3コース攻めにある「イン艇にST合成点で明確に劣るときの減点」だけを4コース攻めへ適用する診断用候補。既存の-10差で-14点、-6差で-9点をそのまま使い、閾値探索はしない。実進入コースの艇を参照し、枠番1・4に固定しない。PR #690の1号艇抑制・重み変更とは別の候補であり、棄却済みfingerprintを再試験しない。

定義以前と以後の保存時点を分けるが、定義後の再計算を締切前に保存済みの候補や正式holdoutとは呼ばない。正式ゲート未登録は `INSUFFICIENT_EVIDENCE`。本命頭の本番選択方式は変えず、自動採用もしない。発見用データで良くなっただけでは反映しない。

## 実行・保存

`.github/workflows/compare-escape-frozen.yml` が変更時・結果照合workflow成功後・日次fallbackに実行し、`data/stats/escape-frozen-comparison.json` のみを書き戻す。main SHA、入力ハッシュ、読み込んだJSハッシュ、公式結果証拠、除外理由を確認する。大きな日次JSONをWorkへ転送し続けない。

元予想を守るため復元用JSONは保存前に作業ツリーから戻す。ゼロ件は改善成功ではない。結果取得失敗・入力欠損・再現不一致・母数不足を区別する。
