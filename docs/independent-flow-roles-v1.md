2026-10-06の「次を進めて」の対象。保存済み公式材料から判断する最初の限定版で、Chat判断全体の再現や販売用予想の完成ではない。判断関数は `scripts/independent-flow-roles-v1.cjs`、固定契約は `config/independent-flow-study-v1.json`。通常AI・オッズ・結果・買い目を入力にしない。

## 根拠と仮説の区別

戦法の意味はBOAT RACE公式の[逃げ](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_02_02_01.html)、[まくり](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_02_02_02.html)、[差し](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_02_02_04.html)、[まくり差し](https://www.boatrace.jp/owpc/pc/extra/enjoy/guide/level2/l2_02_02_03.html)を参照した。以下の事前判定は当プロジェクトの未検証の仮説であり、公式が推奨する予想条件ではない。

公式展示6艇・実進入・STと時刻の既存契約を通ったinput、同じinputHashのjudgmentContextだけを使用。艇番と実進入を分ける。各根拠には元input/contextのhash、艇番、項目名、元の値を保持し、判定を再計算して完全一致を検査する。結果を知った後の追記はしない。

## 固定した展開判定

1. F/Lなどの展示マーカーがある場合、主展開は未確定とする。展示のFを本番のFと読み替えない。
2. 実2〜6コースを実際の一つ内側と比較する。「展示STが内隣より速い」「展示タイムが0.10秒以上速い」「公式コース別平均順位が0.5位以上良い」の3条件を、外からの圧力を調べる仮説として使う。後二つは既存の近似条件。新しい加点・オッズ閾値は作らない。順位の一般戦限定は未確認のまま。順位は元取得から6時間以内だけを使い、nullや期限超過を補わない。一つでも既知の不成立があればfalse、他が成立して必要な値が欠ける場合はunknown。
3. 外攻めの候補ごとに**内側全艇**を確認する。展示STが候補と同じか速い内艇は壁候補。内隣の優位だけで壁を飛び越えたと判断しない。壁なし・圧力成立のまくり枝だけをsupportedとする。展示の並びは本番のスリットを保証しない。
4. 内側優位を基本に、外の圧力判定が全て既知、supportedのまくり枝なし、実1コースの展示STが実2コース以下なら、逃げの参考枝をsupportedとする。「圧力を検出しなかった＝逃げる」と断定しない。
5. supportedが一つ、圧力のunknownとマーカーがない場合だけ、その枝を主展開の**研究上の参考**にする。複数の攻め・不足・支持なしは未確定。艇番や後順位の数字で解消しない。
6. 2コース差しと3〜6コースのまくり差しは条件付きの別枝として残す。旋回時の空き・ハンドル技量はこの入力だけでは確認できず、展示数字だけでsupportedへ上げない。まくり差しのすぐ内側に攻め役がいる場合はその対応を残す。この版は2コース以外の純粋な差しの選定を扱わない。

## 残し／拾い

各枝で6艇すべてに、実コースと役割の理由を記録する。先頭役以外の2着／3着の優劣は未確定で、両方の可能性を保持する。

| 展開の仮説 | 記録する条件付き役割 |
| --- | --- |
| 逃げ | 実2コースの内残し。他艇の着順は未確定 |
| まくり | 内側の壁残り・1コースの立て直し・圧力を受ける内艇・攻め艇のすぐ外の拾い |
| 差し | 先に回る内側艇の残り |
| まくり差し | 内側の攻め役の残り・1コースの残り |

まくられる内艇を自動で圏外にせず、4コースが攻め艇の外側なら他コースと同じ規則で拾い役を残す。役割の記録は実際にその展開が起きたことや2〜3着に来ることの保証ではない。無根拠な候補券作成を避け、この版の `tickets` は空、`selectionImplemented=false`。

8段階の順序は維持する。当地／水面・技量・モーターは材料があってもこの判定にまだ使わず `unimplemented`。後段の数字が前段の展開を反転させない。`fullJudgmentImplemented=false`、`usableForPrediction=false`、`automaticApplication=false`。

## 保存と前向き診断

既存live-noteの同じ公式応答から、通常AI評価前にsnapshot-v3を作る。新しいflowStudyと旧展示優位candidateを同一時点で計算し、元context・方式hashごと既存GitHub artifactへ封印する。公開handoffを先行させ、締切前のremote確認だけを不変receiptへ保存する。新cron・追加取得・Work監視・有料APIは作らない。

日次 `escape-main-audit.yml` が従来レポートの別枠flowStudyを生成する。新方式の最初の有効seal、参考枝の件数、未確定理由、結果待ち、除外を分ける。公式1着との一致は**頭1艇の参考一致率**であり舟券的中率ではない。旧展示優位と同じsnapshotで両方の頭がある行だけ、頭の追加一致／失った一致を比較する。2〜3着は主役が1着だった場合の役割ラベルを観測するだけとし、全艇を含む役割から自明な100%カバー率を作らない。

実着順だけで実際の差し・まくりを創作せず、ROI・払戻・買い目成績も作らない。旧snapshot-v1/v2の件数と混ぜず、新判断を過去原本へ補完しない。既存候補、予想、note本文、公開、コロがしの条件は維持する。採用gate未登録。
