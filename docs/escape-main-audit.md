# 本命・逃げ展開の診断

全24場を対象に `scripts/audit-escape-main.cjs` が保存予想と独立した公式結果を照合する。
実行は `.github/workflows/escape-main-audit.yml`。結果は `data/stats/escape-main-audit.json`。

- 日次予想は既存archiveのハッシュ検証付き復元を先に実施し、primaryをverificationより優先する。
- 全レースnoteは既存 `build-race-review-progress.assess` の不変bundle検査を通す。日次と重なるレースは締切前の最新時点を1件採用する。
- 日次は `analysis-input-contract.preDeadlineReason`、noteは既存の `assess` による独立の締切前・展示・監査契約を守る。条件スナップショットのあるnoteには前者も適用する。元予想や過去履歴を補完・書き換えない。
- 返還・不成立・払戻不明を成績に含めない。1号艇勝利と公式決まり手「逃げ」を分ける。
- 1点100円の仮定による実戦厳選の集計であり、ユーザーの実購入成績ではない。通常候補24点を実戦購入額へ混ぜない。
- 24場、取得経路、保存された方式/コード識別子ごとに集計する。母数0は0%ではなくnull。
- 「候補的中・厳選不的中」は観測事実であり、保存されていない除外理由や原因を推測しない。

## 逃げ技量を検証するための保存修正

`prediction-conditions.capture` は今後の取得分に `escapeEvaluationEvidence` を追加する。
元のコース別選手履歴、今節STを含むエントリー、展示・進入、展開・技量・ST評価を参照分離して保存する。
履歴欠損は `unavailable`。古い予想には現在の履歴を後付けしない。
`note-draft-bundle` の最終保存でも `preRaceConditions` と `verificationEvidence` を保持し、全レースnote側で途中の検証情報が消える問題を修正する。
これは検証入力の欠損修正。過去の再計算用 `frameRiseFallReplayBasis.analyses` には評価済みコース履歴が残る場合があるため、元の全履歴入力の未保存と混同しない。診断はこの既存保存先も使う。
保存した項目だけで全エンジンの完全再現が証明されたとは扱わず、候補比較前に現行予想の再現一致を確認する。

## 逃げ候補を別戦法で採点する不具合

`getRacerSkillRole` が主展開の種類をすべての1着候補に割り当てていたため、外攻め展開の代替1着候補であるイン艇まで「まくり・まくり差し」で採点していた。実際の1コース艇が1着候補なら「逃げ」の既存戦法適性式を使うよう修正する。枠番固定ではなく公式実進入を使い、1着候補でない艇の残し/拾い判定は維持する。
係数・点数上限は変更しない。既存の技量接続は同等の残し/拾い候補の優先順だけなので、主展開や本命頭を直接変更する修正ではない。丸亀9R/10Rの取得済み入力再計算では本命・実戦券集合は旧版と同じ。購入時の再現や的中率改善の実証とは呼ばない。
診断には、保存済み技量評価でこの役割不整合があるレース数と、同じ戦法適性式を正しい逃げ実績に適用した点数を残す。これは買い目A/B比較ではない。

## 本命選択変更までの残り

今回の診断は新たな予想候補のA/B成績ではない。正式採用ゲート未登録は既存phase11の `INSUFFICIENT_EVIDENCE`。
逃げ候補の選択・攻め切りとの比較を修正する場合、固定優先順位と点数条件を維持し、候補作成に使った既知データと将来評価期間を分ける。
履歴を含む保存入力とロジック版で現行が再現できることを確認してから、同一レース・同一購入条件で比較する。
少数高配当依存・場別/期間別の悪化も確認する。今回のユーザーは検証後の反映まで許可済みなので、条件成立時の再承認要求は不要。
