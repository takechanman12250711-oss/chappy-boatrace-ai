# コロがしの資金・結果下書き

2026-10-05の相談を受けた確認用機能。`scripts/note-korogashi-draft.cjs` は、公開receiptとSHAが一致した保存予想を読み、初回1点1,000円・払戻の再投入・最大2〜3レースを試算する。10万・20万・30万円を基本例に、10万円単位の目標を指定できる。目標は最終保有額（最後の払戻＋未投入端数）であり純利益ではない。記事代は別。

## 既存原本との接続

- 対象レースは入力で明示する。オッズからレースや買い目を選ばず、各原本の中心1〜7点を全て保持する。多い買い目を勝手に間引かず、候補・参考を加えない。少点数に絞る予想判断は別工程。
- 既存 `receiptRow`、`settlePublished`、展示検査を再利用する。公開記事、保存原本、種類、時刻、中心買い目、公式結果を照合する。原本・既存記事・成績台帳へ書き込まない。
- 次の計画時刻は前の公式結果取得後で、次の締切まで120秒超が必要。同日内、重複レースなし、最大3回。目標達成・不的中・上限で終了する。未確定・返還・同着・不成立・不一致からは継続しない。
- 2回目以降は100円単位で均等に配分し、余った100円単位は原本順に加算する。100円未満の端数は明示して保持する。全券に100円を配分できなければ停止し、券の削減や追加入金をしない。

## 実行

```sh
node scripts/note-korogashi-draft.cjs --input /path/to/session.json
```

入力は `version: note-korogashi-draft-v1`、`targetYen`、`maxLegs`（2または3）、`legs`。各legは `sourcePath`（既存 `data/note-drafts/...`）、その元記事の`receipt`、`plannedAt`、取得済み公式APIの`result`（未確定なら省略）を持つ。次の候補を見送って終える場合だけ `stopReason: no_suitable_race` を指定する。JSONと日本語下書きを標準出力へ返す。CLIの現在時刻は実時計で、入力から上書きしない。

この入力にはローカルの計画時刻しかなく、コースを締切前に登録したリモート証拠はない。過去入力を使えても検証用の試算であり、実際のコロがし成績として掲載してはいけない。出力は常に `review_only`、`canPublish=false`、`purchaseExecuted=false`、`preRaceCommitVerified=false`。既存note投稿handoffへの接続は行っていない。

## 運用接続 v1（2026-10-06）

確認用CLIとは別に、`note-korogashi-lifecycle.cjs` / `note-korogashi-store.cjs` / `note-korogashi-run.cjs` を既存の `Update note marketing` へ接続する。新しいcron、公式collector、有料API、舟券購入処理は作らない。未登録のコースを毎日自動作成しない。

- 開始は既存workflowのRun workflowで、`korogashi_first_publication_key` に当日の公開済み初回レース（`YYYYMMDD-JCD-R:normal|escape|manshu`）を指定する。目標は `korogashi_targets` に円・カンマ区切り、既定は `100000,200000,300000`。最大回数は `korogashi_max_legs` の2または3。初回キーが空欄なら通常更新だけ。同じ初回・目標の再実行では新しいコースを増やさず、既存の回数や目標も変更しない。iPhoneのGitHub画面から入力でき、PC認証やCookieは不要。実端末での操作確認は別途必要。
- `config/note-korogashi.json` の明示requestも受け付ける。初期値は空で、架空のレースや過去レースを開始設定しない。登録後のrequestは専用状態に残り、設定から消しても履歴は消えない。
- 初回は指定した既存公開記事。継続は公式結果が確定した後、同日・同種類の公開済み記事を締切順に確認し、展示・公開receipt・原稿SHA・中心1〜7点・締切余裕120秒超がそろう最初のレースを使用する。目標別に有利なレースを後付けせず、買い目やオッズから選別しない。公開済みの中心券は全て保持する。
- 運用版の100円単位の余剰配分は**艇番の数字が小さい券順**。公開フォーメーションから同じ配分を再現するためであり、原本の優先順や買い目は変更しない。確認用CLIの原本順配分とは区別する。100円未満は保有、全券へ100円を配れなければ次候補を待ち、当日終了で止める。
- 専用 `note-korogashi-state` branch の `state.json` へ、要求・配分・出典・前イベントhashを持つpendingを保存してからActions artifactへ送る。artifact ID・digest・run/head・GitHub HTTP時刻の秒精度上限を確認し、締切120秒超ならregisteredを追記する。非forceのref更新で競合を停止し、古いイベント・要求・pendingを差し替えない。中断した旧runのpendingは失効で終了する。
- artifact登録だけでは公開実績にしない。既存無料一覧の本文・元記事リンクを匿名ブラウザで確認した実時刻と本文hashをannouncedイベントへ保存する。掲載確認も締切120秒超が必要。未確認・遅延は払戻実績に算入せず、次へ進めない。確認記録の保存が失敗した場合、後から時刻を書き戻さない。
- 結果は既存公式日次データとnoteの公式結果キャッシュを使い、矛盾があれば停止する。的中・不的中・不成立・要照合を区別し、不明を外れや0円にしない。過去予想や研究台帳へ書き込まない。
- 無料一覧に注意書き・目標・開始資金・各段の配分額・時刻・元記事リンク・結果を追加する。買い目は既存有料記事で確認し、コース用の重複課金記事や表紙を増やさない。モデル記録であり実購入・利益ではないこと、記事代別、同じレースを使うコースの結果が連動することを明記する。
- 既存15分間隔と共有投稿キューを使うため、レース間隔・結果取得・公開の遅れで継続できない場合がある。間に合うと保証せず、期限を緩和しない。独立のX送信・通知は追加しない。

## 2026-10-07 コロがし検証対象の公開証明

新規公開だけ `readable-v3` を使用し、本命・押さえ・流し・万舟の区分は維持したまま、有料末尾に `🔄 コロがし検証対象` を表示する。対象は保存済み `baselinePracticalTickets` と予想・記事の実戦厳選が完全一致した1〜7券であり、公開予想の部分集合として再掲する。新しい買い目・追加購入・独立した成績区分ではない。券・オッズ・原本順序・通常成績の定義は変更しない。

- `scripts/note-korogashi-presentation.cjs` が固定書式を生成する。対象券が通常公開区分の和集合に含まれない、参考だけに含まれる、原本不一致、未知の書式なら停止する。無料部分・無料一覧に具体的な券を出さない。
- 公開receiptの `publishedDisplayProof.modelSubset` に原本SHA256・対象券hash・点数を保持し、有料本文全体のhashとともに検証する。コース初回と次段は公開証明を原本から再構築できた記事だけを使う。登録後も結果照合時に同じ証明と配分券を再確認する。
- `readable-v1` の既存「中心の買い目」は、実際の公開proofまたは検証済み旧publisherコードの証拠から一致を確認できた場合だけ対応する。`readable-v2` には対象欄がなく、同じ点数の本命欄を読み替えない。既公開v1/v2の本文・proof・復元コードは保持し、過去原稿へ後付けしない。
- コロがし対象の再掲は公開4区分の和集合・的中判定・区分別成績へ加算せず、別会計の参考予想にも分類しない。既存の事前artifact登録、無料一覧の匿名確認、双方の締切120秒超、状態の追記専用記録は維持する。
- 10月7日桐生6Rは保存中心6券と公開本命6券が異なるv2の確認例として登録を見送った。修正のテスト成功・main反映と、次の適格記事による実コースの事前登録・掲載・公式照合は別に確認する。実購入・入金・決済処理は含まない。


### 過去表示の明示的なreceipt回復

`recover` は従来どおり明示実行だけで、記事の編集・再投稿をしない。claimのリモートrefから確認した不変commitに元原稿が存在し、renderer・公開元adapter・必要な依存コードがレビュー済みの固定版と一致する場合だけ、その版で本文・公開証明を復元する。入力のversion名、現在の日付、原稿のsourceCommitだけでは旧版を選ばない。未確認のhash・欠けた原稿・本文不一致は停止する。v1/v2の記事へv3の検証対象欄を後付けせず、回復をコロがしの締切前公開証拠に昇格させない。
