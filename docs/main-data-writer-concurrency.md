# Main data writer concurrency

Workflows that write generated data to `main` share the `chappy-main-data-writers` concurrency group. Every workflow in that group must set `queue: max` and `cancel-in-progress: false`.

Mixing the default single-pending queue with `queue: max` can replace an older waiting writer when several follow-up workflows start together. The shared invariant keeps pending writers queued while retaining serialization; it does not identify any one workflow as the proven source of a past cancellation.

## Negative-clip comparison and active-100R publication

`collect-frame-rise-fall-negative-clip-ab.yml` and
`check-active-100r-early-monitor.yml` compute outside the shared writer group.
Only `publish_comparison` / `publish_monitor` enter the shared queue. Their
existing triggers and calculation rules remain unchanged. Neither publisher
runs a builder, restores a daily archive, or collects a new prediction.

Before publication, `generated-data-checkpoint.cjs pack` freezes the prepared
Git-save outputs as byte payloads plus a manifest. The negative-clip profile
allows only the selected day's raw JSON, gzip + metadata pair, and its existing
result report. The active-100R profile allows only its existing report. This is
a separate narrow transport; it does not expand `result-report-checkpoint.cjs`
to accept prediction originals. The original raw/archive readers are unchanged.

The compute job uploads a run/attempt-specific artifact with 3-day retention.
Publication requires its exact artifact ID, manifest SHA256, source commit,
profile, target date, and capture run/attempt. Each file's size, SHA256, Git blob,
and allowed path are verified. Missing or mismatched data fails closed. The
capture attempt comes from the successful compute job, so rerunning only a
failed publication job can reuse that same frozen artifact; it does not recapture
old races. An unavailable artifact is a blocker, not permission to rebuild it.

The publisher checks base blobs against the source commit and latest `main`.
For negative-clip it guards raw JSON and both archive files, even when the
save preparer restored the tracked raw file before committing. Changed source
or code stops publication while leaving the uploaded artifact available.
Archive deletion is allowed only as the existing paired transition to a saved
replacement raw JSON. Raw-source and report deletion are forbidden.

A temporary Git index creates a commit from the latest tree, updating only
validated output paths. The caller's branch, index, working tree, unrelated
new predictions, results, notes, and drafts are untouched. No force push,
three-way JSON merge, or rebuilding is used. A moving remote gets at most three
attempts, with full checks each time. A same-content already-persisted bundle
or empty bundle is a no-op; other content conflicts remain failures. Generated
bytes remain in the artifact when the retry limit is reached.

The publication log/summary records source commit, saved commit, artifact ID,
status, and attempt count; the save commit also records the manifest hash and
capture run/attempt. Confirm the saved blobs on `main` before calling a run
persisted. Artifact upload, successful publication, and recovery of an older
failed run are separate facts. This change does not recover the unuploaded
archive from run 38044792998 and does not prove how many unique snapshots that
archive contained. Do not rerun its capture or create historical snapshots to
label that incident recovered.

Publication failures must be reported promptly through the existing Actions failure
notification and task status. Check the failed run’s artifact ID, downloadability,
and 3-day expiry before that retention window ends; do not assume retention
alone proves the data is recoverable. Preserve the failure as unresolved until
the exact generated bytes are safely published or explicitly handed back.
Expiry or missing artifacts never authorize automatic historical regeneration.
