# AI社員の無人勤務を接続する

## 2026-11-13 双方のクラウド起動を接続する依頼

本人が「チャットを閉じた後も双方が自動起動して往復する状態を構築したい」と依頼した。既存の毎時「AI社員の継続開発」をチャッピー側の実行元として再利用し、Claude側は公式Cloud scheduled taskのGitHub `pull_request.labeled` を専用ラベル `chappy-claude-handoff` に限定して使う。新たな毎時勤務、常駐PC、有料APIを追加しない。各サービスの既存利用枠を消費する。

具体的な本人設定、社員への指示、初回検証は [Claudeクラウドタスクとの接続](ai-staff-claude-cloud-task.md) と [保存する指示本文](ai-staff-claude-cloud-prompt.txt) を使う。手順の保存、ラベルの用意、依頼コメントの投稿はClaudeのタスク登録・受領を意味しない。本人のClaudeアカウント内でGitHub Appの接続とタスク保存が必要であり、こちらから確認できるまでは未設定／未確認とする。

`scripts/ai-staff-handoff.cjs` が同じPR・依頼ID・往復回数・headを照合し、create-onlyの予約ラベルで依頼／実行権／返却の重複を抑止する。予約ラベルはPRに付けず、同名作成の競合を実行権の制御に使う。作成後の通信結果が不明なら削除・再投稿せず停止する。同じファイルの編集権を他の開発経路まで強制的にロックする機能ではない。各往復で現在headと編集担当を確認し、最大3往復、本人への最終提示前に依頼を止める。

初回は今回の構築PRの読み取り専用レビューを渡し、Claudeの実行URL付き受領・返却と、その後のチャッピー予定勤務による受領を同じPRへ残す。初回の読み取り確認を実装修正ループの成功やmain反映と扱わない。PR #1461で確認済みの既存GitHub→Work受信は、従来の読み取り専用・タイトル限定のまま保持する。

本人は、チャットを閉じている間もAI社員が判断して作業を進める運用を選択した。社員定義だけでは起動しないため、実際のAIを起動するタスクと、GitHubへ残す作業状態を接続する。

## 実行する範囲

- 本人が依頼済みの未完了課題から、1回に1件を選ぶ。依頼の根拠が不明な課題や、新機能・別サービスは対象にしない。
- カイが入力・担当・完了条件を整理し、必要な社員だけへ委任する。使えるサブエージェントがなければ逐次処理と明示する。
- 調査、依頼範囲の最小修正、必要な検査、独立レビュー、同じPRへの保存まで進める。主担当が社員間の受け渡しを処理し、本人へ各工程の転記を求めない。
- mainへのマージ、予想方式や重みの本番採用、認証変更、新しい公開・再投稿は自動で行わない。固定headの変更・影響・図・検査結果を本人の最終確認へ返す。
- 既存の自動収集・結果照合・公開処理は継続する。それらの成功を無人の社員判断やコード修正の実行証拠にしない。

## 起動元

このサービスが登録・管理する無人のPR開発勤務は、接続済みのタスク機能で本人が確認した頻度の1件だけを使う。これはスクリプトだけの定期実行とは異なり、AIが保存状態を読んで次の作業を判断するため、サービスの利用枠を消費する。新しい有料AI APIや追加契約は導入しない。過去の利用枠抑制方針を変更する対象と回数を本人に明示し、許可された頻度を超えて起動しない。

Claude側の既存予定運用は、[返却 comment 6765565835](https://github.com/takechanman12250711-oss/chappy-boatrace-ai/pull/1445#issuecomment-6765565835)では提案ボードの下書き専用で、GitHub変更・マージ・タスク作成変更をしないと報告された。このサービスのPR開発勤務とは責任範囲を分け、相手のタスクを変更・新設しない。実設定・予定実行は未検証であり、同じPRへの今回の読み取りレビュー返却を、その予定タスクがGitHubへ自動で受け渡した証明にはしない。

停止中の古い開発タスクに、別の実行者や環境が記録されている場合は、再開だけで現在のAI・環境へ移行したと扱わない。実行者と環境を変更できない実行元では旧タスクを停止のまま保ち、現在の実行者で新規1件を作る。他用途の有効タスクや、停止した監視タスクは変更しない。

タスクの作成応答と読み戻しで、タスクID、実行者、指示、頻度、タイムゾーン、有効状態、次回予定、選択環境を確認する。環境情報がnullなら不明、空配列なら添付なしであり、現在の一時workspaceが将来も保持されるとは保証しない。接続・再接続や本人承認の要求が返ったら、登録済みとせずその結果を本人へ返す。

## 各勤務で行うこと

1. GitHubから最新mainの `AGENTS.md`、対象PRの最新コメント・head、前回の残件を読む。主な作業状態はGitHubに保存し、この会話の一時ファイルだけを継続の根拠にしない。
2. 本人確認待ち・他担当の作業中・本人認証待ちを編集対象から外す。同じタスクの別run・前回勤務が実行中と確認できれば、新しい実装を始めず引き継ぎまたは今回を終了する。現在の自分のrunを重複と誤判定せず、競合が不明な同じファイルは変更しない。入力や対象headが変わっていたら照合し、担当記録を原子的なロックとは説明しない。
3. 既存の作業ブランチとPRを再利用する。実装・検査が可能な環境では実際に行い、環境がなければ接続済みGitHubで確認できる差分・保存結果・CIまでに範囲を限定する。未検査を合格へ読み替えない。
4. 大規模分析は既存GitHub Actionsへ任せ、保存済みレポートの鮮度・母数・成功状態を確認する。Workで全期間再計算や長時間の待機を重ねない。
5. 1回の作業ID、担当、入力SHA/時刻、変更、成果物、検査対象head/run、未確認・停止理由、次の具体的な1件を同じPRまたはIssueへ記録する。変化がなければ重複コメントを増やさない。
6. 次回はその記録から再開する。同じ認証切れや同じ原因の失敗を無制限に再試行せず、完了済み工程をやり直さない。

Claude Code側の社員との協業では、同じPRの受領状態・実行元・編集担当と返却headも読む。相手が編集中なら読み取り専用の確認にとどめ、返却された固定headをこちらで独立に確認する。相手が未起動・未認証ならその状態を残し、競合しない依頼済みの別件を進める。相手の起動や同じ依頼の催促を繰り返す新しいタスクは作らない。詳細は [社員の分業運用](ai-staff-operations.md#claude-code側の社員と協業する)に従う。

共有の社員定義がmainへ未反映の間は、対象の準備PRとその現在headを照合して参照し、未反映と明記する。未承認のコードをmainへ適用したり、本番設定を変更したりする根拠にしない。

## 成立を確認する証拠

| 状態 | 必要な証拠 |
| --- | --- |
| 準備済み | 社員定義、作業指示、停止条件、本人が確認する頻度と利用枠 |
| 登録・有効化済み | タスク作成応答と読み戻した設定、実行者、次回予定 |
| 無人実行完了 | 予定実行のrun ID・開始/終了時刻・成功状態・同じrunの結果。設定成功だけでは不足 |
| 作業成果を確認済み | 実際のPR/head、変更内容、検査runまたは保存成果物。単なる通知や計画説明だけでは不足 |
| main反映済み | 本人の最終確認とGitHub上の実反映。上記の実行成功とは別 |

手動試運転が現在の会話へ処理を返す場合、それは会話を閉じた後の実行証拠ではない。初回の予定実行で実際の成果を確認するまで、無人運用が完成したとは説明しない。

Claude/Codex CLIの認証状態と、このサービスが起動するAIの実行可否は別に確認する。失効したCLIや未認証のClaudeを稼働済みと扱わず、タスクで実際に利用できるAIとGitHub接続を使う。認証コード・トークン・私的な利用状況を公開リポジトリへ保存しない。
