# 一周・まわり足・直線の独立した計測値

浜名湖公式の直前情報は、通常展示・一周・まわり足・直線を別区間の値として公開しています。従来の `api/_original-exhibition.js` は同じページを取得していても一周だけを取り込んでいました。この変更は、既存の取得応答からまわり足と直線を別項目で保持し、予想時点の原本に残すためのものです。

外部評価ツールのコードや係数は使用しません。場の公式計測定義に基づく独立した取込です。現時点の対応場は既存と同じ浜名湖（06）だけで、24場共通の計測とみなしません。追加のHTTPリクエスト、新API、新cron、有料サービスは追加しません。

## 保持する値

- `lapTime`：一周。既存の数値・採点経路を維持します。
- `mawariTime`：まわり足。一周とは別の値です。
- `straightTime`：直線。通常展示タイムとは別の値です。
- 各値の公式出典URL、計測項目名・単位・場、解析した同一本文のSHA-256と取得時刻を保持します。

`turnTime` のような意味が曖昧な既存aliasへ、新しいまわり足を流し込みません。欠測の「-」、不正な数値、項目の見出し対応が不明な場合はnullです。まわり足や直線が未計測でも、正しく取得できた既存の一周を消しません。一周が欠測していても、有効なまわり足・直線は保持します。一周の採点入力は従来どおり6艇が揃う場合だけ追加し、不完全な一周を新たに採点へ渡しません。

互換性のため既存の出典識別子 `BOATRACE浜名湖公式・独自計測一周` は維持します。新項目の計測内容は、この文字列ではなく項目名・`MeasurementLabel`・`metricDefinitions` で区別します。

公式表の2段目の見出しは3項目とも同じCSS classを使用するため、CSS classだけから項目を決めません。見出しの項目と本文の列対応を検査します。登録番号6艇と、中央公式の展示タイム6艇の一致という既存の結合条件は維持します。不一致の独自ページを採用せず、中央公式の有効な出走表・展示は保持します。

## 予想時点の保存と参考比較

`entries / beforeInfo` から既存の `ChappyPredictionConditions.capture` へ、値と出典を引き継ぎます。原始入力を保持する `escapeEvaluationEvidence` にも独自計測のメタデータを残します。既存の日次原本・note bundleへの保存経路を使います。

まわり足と直線の同R内順位・平均との差は、項目ごとに分けた参考情報として凍結します。6艇分の同一の定義・出典が揃わない場合は比較不能とし、未測定を低評価へ置き換えません。順位は計測値の比較であり、本番の着順確率ではありません。

参考情報は `reference-only`、`scoreApplied=false`、`affectsPrediction=false`、`usableForPrediction=false` です。core/selectorの点数・重み・役割・券数は変更しません。既存の展示9%枠へ未検証の点を追加せず、数値だけから買い目を作ったり削ったりしません。

source取得時刻と、締切前の予想保存・remote sealの証明は別です。取得時刻だけで締切前保存済みとは判定せず、既存collectorの締切・原本・remote確認条件をそのまま使います。

## 検証できることと未実証のこと

ローカルとCIでは、公式表の列対応、登録番号/中央展示の不一致、欠測、単位/出典/時刻/hash、APIから予想時点snapshotへの接続、参考順位と既存評価の非変更を検査します。過去ページを今日取得した例はparserの項目確認用に限り、当時の予想入力へ追加しません。

確認した旧保存例には一周はありますが、独立したまわり足・直線はありません。この変更だけで的中率が向上したとは扱いません。新たに締切前保存された実測が揃った範囲で、次の順に評価します。

1. 欠測率・出典の一致・計測区間を確認する。
2. 候補の条件を固定し、同じR・同じ券数で比較する。
3. 追加的中・失った的中・純増、的中率、回収率を別々に示す。
4. 結果を見た期間は発見用とし、別期間の評価を残す。

大規模・定期集計は既存のGitHub Actionsを使います。旧 #1336 の相手順候補や、過去の欠測を補った成績は再利用しません。
