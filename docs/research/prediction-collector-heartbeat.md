# 8点検証を止めないための収集未起動対策

2026-09-25。既存のWatch collection healthはcollector終了イベントだけで起動しており、collectorが起動しない時の監視がなかった。取得した最新実行は17:31 JST完了のままで、新しい比較対象も増えていなかった。

既存watchdogへ毎時17分（07〜22時JST）の定時確認と手動起動を追加する。稼働時間は07:00以上22:30未満。mainのcollectorに未完了の実行がある場合、または過去60分以内に実行が作られている場合は何も起動しない。それ以外は直前に再確認し、既存collect-predictions.ymlのmainを1回だけworkflow_dispatchする。

確認APIが失敗した時は再起動しない。POSTの応答不明時に再送しない。実行の受付と収集成功を分け、受付時点ではexecutionConfirmed=false。既存collectorの対象レース・買い目・note監査・同時実行制御は変更しない。過去レースの予想や比較データを後付けしない。

新しい外部サービスやWork実行を使わない。ただしこのwatchdog自体もGitHubのスケジューラを使用するため、実行遅延・欠落を完全に保証する対策ではない。GitHub内部で今回の定時起動が欠けた根本原因まで特定したとは扱わない。

APIは2026-03-10を指定し、200の実行ID付き応答と従来204の両方を受ける。正常応答以外を復旧成功と記録しない。

`node --test tests/prediction-collector-heartbeat.test.cjs`で15件の単体テスト。実際の再起動・保存はmain反映後のActionsと日別原本で別途確認する。
