# 継続台帳の保存競合と8点比較レポート停止の修正

2026-09-26。8点A案の実運用確認の続き。本番予想への採用ではない。

## 実際に起きた失敗

結果収集成功後のrun 36184838528 / job 108235591088は、台帳計算まで成功したが、2026-09-26 05:20:32 JSTのpushが `main -> main (fetch first)` で拒否された。既存workflowには追従処理がなく、後続の8点比較レポート生成もskipped。artifact保存ステップはsuccessでも、実際にはファイルなしで未保存だった。

## 修正範囲

- 専用の一時worktreeへ最新mainを取得し、既存の台帳計算コードをそのまま実行する。元の作業ツリー・index・原本は触らない。
- 書き込みを `data/stats/continuous-performance-ledger.json` 一つに限定。異常な出力や他ファイルへの変更は公開しない。
- 競合でmainが進んだ場合は最新mainから再計算する。上限3回。force-pushや古い台帳の競合強制解決は行わない。
- pushの応答が不明なら再取得してcommitの到達を確認し、成功済みの二重保存を避ける。mainが進んでいない拒否は失敗として表示する。
- 台帳保存が失敗しても、checkoutとNode準備が成功しておりキャンセルされていなければ、8点比較レポートは別途生成する。生成成功の場合のみartifactを保存し、ファイル欠落はエラーにする。
- 本番の選定・救済・購入判断・note・A条件・90点境界・台帳の集計式は変更しない。

## 再現テスト

`node --test tests/continuous-ledger-persistence.test.cjs`

ローカルのbare Git repositoryと別writerを使い、競合する本物のpushを再現する。正常保存、変更なし、入力変更後の再計算、同じ台帳への競合、2回競合からの回復、上限超過、権限拒否、応答不明後の成功照合、入力変更遮断、出力異常、元作業保持、workflowの独立条件を検証する。

試験成功とmain上の保存成功は分けて確認する。テスト内の小さい台帳生成器は転送・保存の試験用であり、予想精度の検証ではない。

## 確認時点の8点観測

基準main 826d4a6b952b013cbbd316156b197217c35a0f15。9/25・9/26を合わせ45正本行、比較保存19、未記録26、読み取りエラー0。新規8点は戸田1R・多摩川1R・丸亀1R・徳山3Rの4件。戸田・多摩川は独立追加券の置換で、A条件の候補補完には該当しない。丸亀・徳山は救済による補完券の上書きがない。したがってA発動0を維持し、件数を増やすために条件を広げない。結果JSONの未確定と実際の未終了は同義ではない。

9/25結果原本は144R確定済み。失敗した台帳jobの再計算は直近100Rが33的中・回収率92.50%・-6,530円だったが、そのjobではmain保存に失敗している。以前の109.99%を現在の成績として再利用しない。修正後の実行でmain保存値を確認する。
