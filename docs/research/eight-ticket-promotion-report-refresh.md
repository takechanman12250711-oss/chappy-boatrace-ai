# 8点A案：収集後更新と原本読み取りの修正

2026-09-25。PR #1081の検証専用接続の運用修正。本番採用ではない。

## 確認した問題

- 既存の別レポートは結果収集完了時だけ更新され、予想収集完了時には更新されなかった。
- 日別JSONだけを列挙していたため、圧縮原本だけの保存日を見落とす。
- 比較データのない行を読み込み時に除いていたため、未記録と対象外の内訳を追えなかった。

## 修正

同じ成績workflowで予想収集の正常終了も受ける。予想収集の場合は読み取り専用の別jobだけで比較レポートを生成し、通常台帳の再計算・書き込み・再収集は行わない。結果収集時の従来経路は維持。

日別JSONと圧縮原本の日付を合わせ、既存metadata契約・圧縮前後のSHA-256を確認する。新しい日別JSONがある場合は古いarchiveで上書きしない。読み取りは原本を書き換えない。欠損・破損はsourceDiagnostics.complete=falseとerrorsへ記録し、正常な0件と区別する。

sourceDiagnosticsに正本件数、比較データ保存件数、未記録件数、最新の比較保存時刻を保存する。未記録を保存漏れと決めつけず、反映前の旧実行等も含めた確認対象として扱う。

A案の条件・90点境界・8点維持・自動採用禁止は変更なし。過去予想への比較データ後付けもしない。

## 実データ確認

基準main 895428226318941aecee157b49b9acec20c1e0aa。9/25原本は正本30R、比較保存4R、比較未記録26R。比較保存4Rは全部8点対象外で、有効8点0・A発動0のまま。これは新たな改善効果ではない。

予想collectorは15分間隔設定だが、確認時点の最新完了は17:31 JST。その後の実行が増えない原因を、このreport修正で解決したとは扱わない。更新は実際に収集が完了した場合に限る。
