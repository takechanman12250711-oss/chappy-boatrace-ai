# チャッピーボートレースAI 運用手順

## 正本

開発・修正・確認は必ず GitHub の `main` を基準にする。

優先順位：

1. GitHub `main`
2. 最新の未マージPR
3. 引き継ぎ資料・チャット履歴

古いブランチや古い資料を `main` より優先しない。

## 本番構成

- フロント：GitHub Pages
- 正式URL：`https://takechanman12250711-oss.github.io/chappy-boatrace-ai/`
- データ取得API：Vercel
- リポジトリ：`takechanman12250711-oss/chappy-boatrace-ai`

Vercel上の古いフロント表示は本番正本として扱わない。

## 作業開始前

1. GitHub接続アカウントを確認する。
2. 対象リポジトリへの権限を確認する。
3. `main` の最新コミットを確認する。
4. 開いているPRと作業ブランチを確認する。
5. 同じ修正が既に `main` に入っていないか確認する。
6. `scripts/preflight-connections.js` を実行する。

## 修正手順

1. 最新`main`から専用ブランチを作る。
2. 変更内容・理由・影響範囲を整理する。
3. 最小差分で修正する。
4. 回帰テストを追加または更新する。
5. Draft PRを作成する。
6. `main`との差分、遅れ、競合、変更ファイルを確認する。
7. CIまたは同等のテスト結果を確認する。
8. 承認後にDraft解除し、squashマージする。
9. マージ後にPR状態と`main`反映コミットを再確認する。

## 変更禁止事項

承認なしに以下を変更しない。

- 予想優先順位
- 70点の自動選定基準
- 展開・印・買い目生成ロジック
- 通常5〜7点、成立展開時最大10点のルール
- オッズの用途
- 本番公開先

## 障害時の確認順

### GitHub操作ができない

1. 接続アカウントを確認する。
2. リポジトリ権限を確認する。
3. GitHubコネクタの読み取りを試す。
4. 書き込み前に小さな読み取り操作で接続を確認する。

### 本番へ反映されない

1. PRが本当にマージ済みか確認する。
2. `main`のコミットSHAを確認する。
3. GitHub Pagesの公開元が`main`か確認する。
4. ブラウザキャッシュ・PWAキャッシュを確認する。
5. API障害とフロント障害を分けて確認する。

### APIが取得できない

1. Vercel APIの稼働を確認する。
2. フロントの接続先URLを確認する。
3. GitHub Pagesの問題と混同しない。
4. APIレスポンスと画面描画を別々に確認する。

## マージ前チェック

- [ ] 最新`main`から分岐している
- [ ] `main`から遅れていない
- [ ] 競合がない
- [ ] 変更ファイルが想定どおり
- [ ] 予想ロジックの意図しない変更がない
- [ ] テストが変更内容を実動作で検証している
- [ ] Draft解除前に承認済み
- [ ] squashマージを使用する
