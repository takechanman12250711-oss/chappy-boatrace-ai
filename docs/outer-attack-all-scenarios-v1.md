# 外攻め全体の前向き比較と収集範囲

2026-09-22のユーザー承認：全開催からの取りこぼしを確認し、候補欠損を修正した上で、既存外攻めA/Bを維持して対象外の外頭・5/6艇・複数攻めを別枠検証する。本番買い目、note公開条件、既存事前登録gateは変更しない。

## 確認した原因

- 2026-09-22公式結果一覧は168R、日次の重複除外入力43R、独立した展示後source9R。旧中央保存16Rの比較は2R、13Rは比較不成立、1R未照合だった。
- 日次 `compactVerificationPayload` / `compactPrediction` が評価済み候補を保存しておらず、20260922-18-7、20260922-10-11の候補プールは空だった。候補0を本当に候補がないと断定できなかった。
- 独立収集は未来の全レース取得を終えるまで予想を保存しない構造だった。展示が揃う短い時間帯の取りこぼしを観測する永続記録もなかった。これが全欠損の唯一の原因と断定はしない。

## 修正

日次の新規予想で既存生成器が作った最大120券の小さな候補メタデータを保存する。再圧縮では保持だけ行い、過去行へ候補を後付けしない。
独立収集は全開催予定を記録し、締切1時間以内を締切順3Rずつ処理する。各バッチの展示確認・予想・独立source保存を完了してから次の取得へ進み、4分を超えた残りは次回へ明示保留する。2分前の生成停止は維持。
予定・取得失敗・展示待ち・締切超過・保存の観測を `data/verification-coverage/YYYYMMDD/<hash>.json` へ不変保存。予想収集が失敗しても、既に作成済みの証拠を既存writerが保存する。
GitHub cronの実行遅延がなくなったとの保証ではない。未観測の過去レースは `no-collector-observation` と表示する。

## 新しい比較契約

`outer-attack-all-scenarios-v1` は新規締切前、公式展示6艇確認済みの独立sourceにだけ保存する。既存の外頭forward shadowや旧3/4艇・2/3着A/Bへ混ぜない。

- 対象攻め艇：既存候補生成器の qualified 展開枝の attackerBoatNo が、公式展示進入3〜6コースにいる艇。5・6号艇や複数の攻め艇も同じ根拠契約で扱う。
- 攻め艇別、1/2/3着別の独立variant。候補は該当の展開枝を持つ `evidenceQualified` 券だけ。
- Aは実戦厳選の元券、Bは本線と正式2券フォーメーションを保護して他分類の末尾1券を置換。購入適格フラグ、既存priority、券番号の順で候補を固定する。新しい予想スコアやオッズ判定は作らない。
- A/Bとも1券100円、同点数・同額。元券に既に含まれる候補、対象券なし、保護外券なしも状態として保存し、全対象と実際の変更レースだけの両方を集計する。
- 同一レースは最初の有効保存だけ使用。異なる予想方式と攻め艇/着順variantは別集計。variant件数をレース件数として合算しない。
- 公式確定結果を既存の日次結果・独立ledgerから読む。日次pendingで独立確定を隠さない。不成立・返還は採点対象外、払戻欠損を0円にしない。
- **本番採用gate未登録**。これは前向き比較・発見用の別枠であり、100Rで自動採用しない。結果に応じた閾値探索や過去の候補再生成も行わない。
