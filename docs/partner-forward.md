# 相手選定の前向き100Rチェックポイント

工程管理: #1214。過去の発見用比較を将来成績に混ぜないための研究接続。

## 固定条件

`config/partner-forward.json` が方式・選定コードSHA256・最初の100Rを固定する。Aは保存実戦券、Bは既存の優先点による相手再選定、DはBが保存1・2着組を消す場合にAを維持する案。全券の点数・頭別配分を維持し、オッズや公式結果は生成へ渡さない。C（場別履歴）、E（完全根拠優先）、旧順位モデルは比較に混ぜない。

現行方式に一致する通常noteの不変原本だけを対象にし、既存assessで展示・監査・締切前時刻・予想原本・選定証拠を検査する。実進入6艇と変更可能な1コース頭枠を必要とする。公開可能性・有料購入・的中は対象条件にしないが、入力は監査済み通常原稿のため全開催成績ではない。

開始はこのコードがmainに反映され、初めてリモート保存確認に成功した時点。固定された過去日を再実行しない。同じRの初回の有効なリモート確認を採用し、後の更新で上書きしない。同時刻はraceKey順。最初の100Rに結果待ち・返還等を含めて枠を固定し、有利な結果への入れ替えや途中終了をしない。方式変更や選定コード変更は同一試験に混ぜず、コードhashが違えば停止する。

## 保存と時刻証拠

既存 `live-note.yml` の5分収集後に、まだ締切前の当日原稿からA/B/Dを `/tmp/partner-forward-seal` へ生成する。GitHub Actions artifactへ保存した後、公式APIでartifact ID・digest・名前・run ID・headを照合する。API応答のDateの1秒上限を確認時刻に使い、候補生成→artifact作成→確認の順序と確認時刻が締切前であることを要求する。ローカルのselectedAtだけをリモート保存証拠にしない。

遅延分はlateとして前向き件数へ入れない。確認できた候補とreceiptだけを `data/partner-forward/YYYYMMDD` に内容hash付きで不変保存し、既存source-only writerを使う。途中失敗でもnote保存・投稿の既存処理を優先し、研究失敗は最後にworkflow失敗として明示する。新しいcron・有料API・Workの常時監視は追加しない。

artifactは90日保存。receiptはリポジトリへ残るが、元artifactの取得期限とは区別する。生の候補だけ・アップロード途中・確認失敗を保存済みとしない。

## 集計と判定

既存 `escape-main-audit.yml` で `node scripts/partner-forward.cjs report` を実行し、`data/stats/partner-forward-report.json` を保存する（日次更新）。締切前に保存した候補だけを既存公式結果と結合し、候補を再生成しない。未確定はpending、返還等は除外理由付きで枠に残す。1券100円の仮想成績として、A/B/D別に的中・投資・払戻、追加・喪失・純増を出す。

100件は固定の研究確認点であり、採用gateではない。本候補に登録済みの採用gateはないため `INSUFFICIENT_EVIDENCE`、本番変更・自動採用・予想利用の各フラグはfalse。既存の別候補の合格条件を転用しない。ユーザーの工程内承認は取得済みだが、それを検証成功の代わりにしない。本番反映は別PRと既存の採用手順で行う。

## 検査

`node --test scripts/test-partner-forward.cjs` と `node scripts/test-note-source-concurrency.js`。実原稿契約を満たす合成入力の生成、締切後停止、根拠・方式・コードhash、頭別点数、リモート識別、HTTP時刻の丸め、同レースの重複、未確定、公式精算、原本不変を確認する。テストの仮想日時・合成レースは前向き実績へ保存しない。
