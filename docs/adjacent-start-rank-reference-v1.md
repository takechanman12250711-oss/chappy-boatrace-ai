# 内隣展示・公式コース別ST順位の近似判定

2026-10-06の「舟券太郎の条件に近い形で実装を進めて欲しい」という依頼に対応。
core世代は `ai-core-v4.8.8-adjacent-start-rank`。通常の内隣展示差と9%枠の配点は維持する。

## 元の条件と今回の違い

元資料（ユーザー提供の表と動画 https://www.youtube.com/watch?v=2CTJeDkz-ak ）は、
内隣より展示タイムが0.10秒以上速く、一般戦の平均スタート順位も0.5以上良い艇をスーパーとする。
一般戦平均の厳密な算出期間・順位母数は資料から確定できない。

今回の取得元は公式の選手別ページ：
https://www.boatrace.jp/owpc/pc/data/racersearch/course?toban=4363
「コース別平均スタートタイミング」と「コース別スタート順」は別の表である。
後者だけを取得する。選手登録番号と表の6コースを検査し、「-」はnullにする。
2026-10-06の実HTMLで、登録4363の値が1〜6コース順に2.50、3.00、2.80、3.60、3.80、3.50と解析できることを確認。

このページは一般戦限定であること、順位の集計期間・サンプル数を明示していない。
別ページの期間や出走回数を、同一の順位母数と推測して補わない。
参考として公式配布の期別データ仕様には期間・コース別進入回数・平均スタート順位があるが、
今回のHTML取得値にその期間や母数を転記しない：
https://www.boatrace.jp/owpc/pc/extra/data/layout.html

## 判定・予想への接続

- 展示後の公式進入6艇が揃った場合だけ、実2〜6コースの艇を実際の一つ内側と比較する。
- 自艇はその進入コースの平均順位、内隣艇は内隣の進入コースの平均順位を使用。
- `内隣の平均順位 - 自艇の平均順位 >= 0.5` と既存の展示0.10秒条件を両方満たす場合に近似成立。
- 当日の展示ST順位、平均ST秒を6艇で並べた順位、今節平均順位には置き換えない。
- `startRankReference.combinedAlert` は近似判定。厳密な一般戦スーパーの `superAlert` は、通常展示条件成立時もnullのまま。混同しない。
- 中心艇の両条件成立は展開の補助説明へ、展示だけの優位は「順位の裏付け不足」の注意へ渡す。外隣の両条件も中心艇への注意として説明する。
- 新しい数値加点、頭固定、券の追加・削除は行わない。`referenceOnly=true` / `scoreApplied=false`。今回の比較は説明根拠の接続であり、順位を用いた買い目変更や性能改善の実証ではない。

## 取得と不変保存

`api/race.js` が既存公式解析の後に `api/_official-start-rank.js` を呼ぶ。
当日JST・展示6艇・公式進入6艇・選手登録番号6人が揃った場合だけ取得する。
過去日と将来日のレースに現在の選手ページを結合しない。

最大6人を並行取得。各人は本文も含めて3秒で打ち切り、失敗しても既存予想へ戻る。
公式の欠測セルにグラフと数値のダッシュが重複する場合は、そのコースだけnullとし、他コースの実測順位を保持する。欠測を0位や平均値へ変換しない。
プロセス内で同日・同一選手のリクエストを共用し、成功6時間・失敗1分、最大256件のキャッシュを使う。
キャッシュ条件は通信量と待ち時間の制御であり予想基準ではない。新cron・有料API・新UIは作らない。

各入力にURL・登録番号・6コース値・取得開始時刻・HTMLのSHA256・取得状態を保存する。
期間・順位母数はnull、母集団は `general-only-unconfirmed`。取得不能と閾値不成立を区別する。
比較に使用した値と出典は既存の `adjacentExhibitionEvidence` と元entriesに不変保存され、
正規化したboatsにも保持される。既存のnote bundle経路をそのまま使用する。過去の保存予想は変更しない。

## 検証

`node scripts/test-official-start-rank.js` は公式型HTMLの表識別、登録番号照合、欠損、異常値、
重複進入、0.5位境界、進入変更、通信停止、共有キャッシュの分離、過去補完禁止、
実APIハンドラ→core→説明→保存を確認する。現行と近似入力追加後で艇指数と展開点が一致することも検査。
既存の展示、ST、API解析、保存、キャッシュ読み込み検査を併用する。
CI成功や取得可能であることを、的中率・回収率の向上とは扱わない。

一般戦限定の出典・集計期間・件数を確認できた場合は、今回の近似と別の入力契約で接続する。
全レースの順位を一般戦へ読み替えず、一般戦の順位が未取得の過去原本へ後付けしない。

## 画面用APIとの共有（2026-10-06）

Vercel上の公式順位ページ取得は、DNS/TCP/TLSが約11msで終わってもHTTP応答ヘッダーが届かず3秒で失敗することをプレビューで確認した。6秒延長・同時数2・native httpsへの変更でも取得できず、原因をHTML解析や欠測セルと混同しない。

既存live-noteの公式レスポンスから、AI評価前に取得済みの順位だけを一時保存する。記事の公開handoffと不変証拠の保存を終えてから、同じ直列ジョブが `data/official-start-rank-cache/YYYYMMDD.json` を更新する。新しい公式取得やcronは増やさない。保存原本のwriterは変更せず、別の限定writerが作業ツリーの無関係な変更を拒否し、対象の日次キャッシュだけを非forceでpushする。

APIは固定リポジトリmainの当日ファイルを公式出走表・展示と並行して取得する。待ち時間は本文を含め2秒。各選手の登録番号・公式URL・SHA256・数値範囲・当日JST・元取得から6時間以内・未来時刻でないことを再検査する。キャッシュの更新時刻を公式取得時刻へ置き換えない。欠測コースはnull、一般戦限定は未確認、参考扱いを維持する。APIの `officialStartRankCollection.sharedAvailable` が共有経路から返した選手数を示す。

共有されていない選手は従来の3秒以内の公式取得へ戻る。自動収集前のレースや通信失敗では順位が不足することがあり、全レース取得保証ではない。日次キャッシュは事実データの配信用であり、締切前封印の代替や過去予想の再生成には使わない。

検査: `node --test scripts/official-start-rank-cache.test.cjs`。API側では共有読み込み・混在取得・6艇共有・過去日不使用・本文停止のテストを実行する。
