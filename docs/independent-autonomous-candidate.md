# 独立候補の無人生成・前向き検証 v1

この実装は **新しい研究仮説**。停止したChat定期タスクの判断をそのまま移したものではなく、有料記事・コロがしの予想元にもならない。既存の人の役割評価による `independent-role-selector-v1` は変更しない。

## 固定する最初の仮説

`independent-exhibition-dominance-v1` は、公式6艇進入・展示ST・展示タイムが揃った時点で次を計算する。

1. F/L等の展示マーカーがある場合は見送り。
2. 展示STが他の全艇より速く、展示タイムが他の全艇以下である艇が1艇だけいる場合、その艇を仮の頭とする。いなければ見送り。
3. 頭が実際の1コース艇ならescape、それ以外ならupset。枠番1を1コースとみなさない。upsetは高配当の保証でも「万舟記事」の判定でもない。
4. 残り5艇の2・3着20通りを列挙。着順ごとの展示STを比較し、両位置で同等以上かつ一方で上なら優位。位置間で優劣が交差する場合は未解決のまま残す。STが両位置とも同値の場合だけ展示タイムを比較する。
5. 他の券に優位を取られない最初の集合を全部残す。1〜7点なら候補、8点以上なら見送り。点数を埋めず、同値を艇番やオッズで切らない。表示順のみ艇番順。

これは展示の相対優位が本番へつながるかを調べる限定的な仮説で、採用済みの展開理論ではない。差し・まくりの判断、残し/拾い、当地/水面、技量、モーターは未実装と明記する。合意済み8段階の総合判断を再現したとは説明しない。恣意的な点数加算、オッズ条件、通常AIの頭・買い目・評価・結果は入力しない。方式を変更する際は新しい版・コホートとし、この検証へ混ぜない。

## 既存処理への接続

`live-note.yml` の既存公式取得を共有する。`evaluateTargets` が通常モデルや履歴補正を呼ぶ前の公式応答から、日付・場・R・取得時刻・公式URL・6艇の進入/ST/展示タイム/マーカーだけを明示抽出する。公式HTML原文ではなく、既存parserの解析済み公式データの保存である。

新しい取得ループ、cron、Work定期タスク、有料AI APIは追加しない。対象は既存live-noteが実際に取得するレース。通常原稿保存済み、実行予算超過、取得失敗等で未取得のレースを含め、全開催の独立監視が完成したとは扱わない。展示不足は次回取得待ち。完全入力での最初の締切前リモート保存を、候補/見送りにかかわらず固定する。

候補は一時領域へ保存し、既存記事の保存・公開handoffを先に進める。その後GitHub artifactのID・digest・run/head・サーバー確認時刻を照合し、締切前だけ `data/independent-autonomous-forward/YYYYMMDD/<raceKey>-<sha>.json` へ不変保存する。保存時点の残り時間は120秒超。artifact確認が締切以後なら正式母数へ入れずlateとしてログに残す。通常AI生成や記事監査が失敗しても、すでに取得した候補を後続のalways処理で保存する。研究失敗は公開handoff後にworkflow失敗として表に出す。

## 結果と未完了部分

既存の日次 `escape-main-audit.yml` が `data/stats/independent-autonomous-report.json` を更新する。escape/upset別に候補数、結果待ち、除外、的中率、1点100円仮定の購入額/払戻/回収率を出し、見送り理由を別集計する。公式結果の矛盾、返還/中止、払戻不明を的中や外れへ混ぜない。通常AI・旧Chat予想との優劣比較、実購入・実販売の成績ではない。

configにコードSHAと方式を固定する。`adoptionGate:null`、`usableForPrediction:false`、`automaticApplication:false`。性能や本番採用は未検証。今後必要なのは実レースでの収集・照合確認、仮説の評価、8段階判断の未実装部分の検討、採用条件の事前登録と別期間での検証である。件数やCI成功だけで公開を有効にしない。
