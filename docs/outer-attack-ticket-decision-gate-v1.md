# 外攻め買い目A/B 事前固定判定ゲート v1

## 目的

`outer-attack-ticket-settlement-v1`が保存する、現行Aと同点数・同資金の外攻めBを、結果を見てから基準変更しない方法で判定する。

対象Bは次の3系統を別々に扱う。

- `cover`：押さえ末尾1点置換
- `flow`：フォーメーション末尾1点置換
- `hole`：万舟末尾1点置換

3案を混ぜず、各案が独立して固定条件を通過した場合だけ承認候補にする。

## 事前固定

判定条件は `config/outer-attack-ticket-decision-gate-v1.json` に固定する。

- 固定日時：2026年8月31日 10:40 JST
- 前向き集計開始：2026年8月31日 11:00 JST
- 元main：`ee644d55b889c0ff38f198b9747c9c4d86c83425`
- 閾値探索：行わない
- 本番自動反映：行わない
- 最終採用：ユーザーの明示承認が必要

開始時刻より前の行、結果後に作った振り返り予想、時刻順不明、結果を予想生成に使用した行は主判定から除外する。

## 件数段階

| 前向き比較件数 | 扱い |
|---:|---|
| 0〜99R | 収集継続 |
| 100〜249R | 害の早期確認だけ行う |
| 250〜499R | 中間候補。通過しても本番採用せず500Rまで固定条件で継続 |
| 500R以上 | 最終条件を全て通過した案だけ承認候補 |

日付の偏りを避けるため、中間判定は10日以上、最終判定は20日以上を必須とする。

## 害の早期確認

100R以上で、次の両方が成立した場合は`harm-review`とする。

- Bの的中純増がA比−3R以下
- Bの回収率差がA比−10ポイント以下

ここで閾値を調整せず、人による確認へ止める。

## 250R中間条件

次を全て満たすこと。

- 的中純増：+3R以上
- 的中率差：+1.0ポイント以上
- 利益差：+1円以上
- 回収率差：+5.0ポイント以上
- 対応あり片側検定：`p ≤ 0.10`
- 前半・後半とも的中純増0R以上
- 前半・後半とも利益差0円以上
- A/Bの投資額一致率100%
- 最大の単一レース利益差を除いても利益差がプラス

通過しても状態は`interim-candidate-hold-to-500`であり、採用しない。

## 500R最終条件

次を全て満たすこと。

- 的中純増：+5R以上
- 的中率差：+1.0ポイント以上
- 利益差：+1円以上
- 回収率差：+5.0ポイント以上
- 対応あり片側検定：`p ≤ 0.05`
- 前半・後半とも的中純増0R以上
- 前半・後半とも利益差0円以上
- A/Bの投資額一致率100%
- 最大の単一レース利益差を除いても利益差がプラス

全条件通過時だけ`approval-candidate-human-review`とする。買い目へは自動反映しない。

## 複数案が通過した場合

次の固定順で、人が確認する先頭候補を1案だけ示す。

1. 最大の単一レース利益差を除いた利益差が大きい
2. 対応あり片側検定のp値が小さい
3. 的中純増が大きい
4. 回収率差が大きい
5. 事前登録順 `cover → flow → hole`

これは表示上の確認順であり、自動採用順ではない。

## 読取経路

判定ゲートは成績分析を開いた時の任意読込に置く。予想開始の必須経路には接続しない。
