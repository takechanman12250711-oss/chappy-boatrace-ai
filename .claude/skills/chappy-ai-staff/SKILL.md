# チャッピーAI社員の分業

最初に最新mainの `AGENTS.md` と `docs/ai-staff-operations.md` を読む。社員の名前と担当は `staff.html` を維持し、既存のスキル・保存結果・Issue/PRを再利用する。

1. 主担当はカイの統括役として、依頼の範囲・完了条件・作業ID・次の担当を整理する。単独で済む作業に全社員を起動しない。
2. 独立した仕事だけを必要な社員へ委任する。まず2〜4名程度とし、担当の正本 `.claude/agents/chappy-<社員の英名>.md` の本文、対象・入力SHA/時刻、編集範囲、返却条件を渡す。この会話では実際に使えるサブエージェントを使い、Claudeの設定ファイルがCodexへ自動登録されたとは扱わない。
3. 同じファイルの編集担当は1名。入力や先行成果を必要とする作業は順に渡す。実装と独立レビューを分ける。
4. 担当は、確認事実・成果物・検査と対象head・未確認/停止理由・次の1件を主担当へ返す。必要な記録は既存の同じIssue/PRへ集約し、不要な台帳や重複Issueを増やさない。
5. 主担当は結果を統合し、何が完了し、何が残り、次に何を進めるかを短く返す。割り当てただけの仕事、未取得の数字、起動していない社員を実行済みへ読み替えない。

社員定義は依頼を受けた実行中の会話で使う。閉じた後の無人判断を保証せず、既存Actionsの実行を社員モデルの判断と説明しない。Claudeへの本人認証・Codexとの直接接続とは別に扱う。

Work定期監視・新cron・有料API・追加契約・自動マージは追加しない。予想/結果/原本/買い目をこの設定で変更せず、予想採用や公開は対応する既存スキルと本人方針に従う。main反映は既存の最終確認を維持する。
