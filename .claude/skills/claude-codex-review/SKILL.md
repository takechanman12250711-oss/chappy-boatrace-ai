name: claude-codex-review
description: Claude Codeが実装したチャッピーのコミット済み差分をCodexの読み取り専用レビューへ渡し、同じPRの検証とmain反映まで引き継ぐ。Web/iOSの別環境でも固定base/headで協業する。
---

最初に `AGENTS.md`、`docs/claude-codex-development.md`、`docs/development-approval.md` を読む。公式自動受け渡しを使う場合は `docs/claude-codex-auto-handoff.md` も読む。2026-11-19の本人指示により、依頼済み開発は個別マージ許可待ちを挟まず反映まで進める。

1. 本人の依頼範囲、開始時base SHA、実装後head SHAを固定する。自動更新されたmainを開始時baseへ読み替えない。
2. 同じ環境にChatGPT認証済みCodex CLIがある場合、差分を作業ブランチへコミットして `node scripts/claude-codex-review.cjs --base <base SHA>` を実行する。未コミット変更がある場合はレビューを開始しない。
3. レビュー本文とreceiptの対象SHA・完了状態・指摘を読む。`completed` は実行完了であり、指摘なし・検証合格・新しい行為への許可を意味しない。失敗やstaleを成功へ読み替えず、レビューhelperの読み取り専用境界を維持する。
4. 指摘を依頼範囲で修正したら新headで必要な検査・レビュー・既存CIを行う。旧headの結果を転用しない。Codexが使えない場合は未実施と明記し、利用可能な独立レビュー経路で確認する。必要なレビューが未完了なら完了扱いにしない。
5. Web/iOSなど別環境では同じGitHubリポジトリのPRへ保存し、PR番号・固定base/head・検査・残件を共有する。CodexのAutomatic review/Review triggerとClaudeの対象PRのAuto-fixは実際の設定と結果を確認する。Draftで必要ならReady for reviewにするが、レビュー完了と扱わない。同じheadの進行中レビューへ手動依頼を重ねない。修正は指示上最大3回とし、不明・範囲外・認証失敗・同じ原因の再失敗では早く停止する。有料API・認証複製・botメンションworkflowで代用しない。
6. 同じPRの変更・影響・フローチャート・base/head・検査・未確認点を共通資料に残す。「このPRをGitHubで確認」と管理画面の「設定・開発確認」は任意の読み取り導線であり、個別許可の必須ゲートにしない。管理画面の共有URLを開くだけではGitHubへ通信せず、本人の照合操作で固定headが一致した場合だけリンクを有効にする。不足・不一致・取得失敗では無効にする。
7. 利用中のAuto-fixを停止し、進行中修正の終了を確認してPRとmainを再取得する。現在headに対応する独立レビュー・CIの成功と未解決指摘なしを照合する。停止・終了が不明ならその不足を報告し、反映準備完了と扱わない。人の転記やbotの受付だけをレビュー完了証拠にしない。
8. mainの変更ファイルと依存影響を確認する。重複・依存変更があれば最新mainへ更新し、新headで必要な検査・レビュー・CIを行う。非重複で依存影響もない場合は理由を記録して続行する。required checks・required reviews・権限を満たした固定headを `sha` に指定しREST APIでsquashマージする。個別許可を再度求めず、GitHubのマージ状態とmain反映を確認して報告する。自己Approveや要件緩和はしない。

本人が特定PRの個別確認・保留を明示した場合だけ、`docs/development-approval.md` の任意確認手順を使う。会話の選択質問ボタンが使えないことや、表示資料の準備を理由に通常の依頼済み作業を停止しない。全環境でのモデル起動・表示確認を追加の必須工程にしない。

研究から本番採用は別変更として検証・採用gate・封印条件を守り、研究結果だけで切り替えない。採用まで既に本人依頼の範囲なら同じ許可を再度求めない。新課金・実購入・履歴削除など未依頼行為へ許可を広げず、原本・会計・公開条件・認証境界を維持する。新しい自動マージbot・workflowを追加しない。

PR #1343と `[連携確認・マージ不要]` PRはAuto-fix対象から除き、確認済みheadを変更せずDraft・未マージで残す。このスキルは常時実行・本人ログイン・自動返信の機能ではない。CLI導入、実モデル応答、受領、レビュー、CI、main反映を区別し、未確認の連携を成功と説明しない。認証コードやトークンを会話へ求めない。
